# Граф Кэли LRX: точный диаметр в Lean 4

**Авторы: S. Uskov, A. Chervov, F. Levkovich-Maslyuk, I. Litvak, A. Smolensky, A. Soibelman, Dia Taha.**
[Авторство](AUTHORS.md) · [English](README.md)
S. Uskov — ORCID: [0009-0006-5845-7013](https://orcid.org/0009-0006-5845-7013).

В Lean 4 формализован точный диаметр графа Кэли группы перестановок Sₙ
с тремя образующими: L — циклический сдвиг, R = L⁻¹, X — обмен первых
двух позиций. Каждая буква считается одним ходом. Для каждого целого
n ≥ 4 диаметр равен **n(n−1)/2**. Задача соответствует
[OEIS A186783](https://oeis.org/A186783).

Доказаны обе границы. Дополнительных комбинаторных предпосылок нет;
условие `NeZero n`, необходимое определению образующих, следует из n ≥ 4.

## Главная теорема

[`LRX.exact_diameter_all`](LRX/SharpDiameterAll.lean):

```lean
import LRX.SharpDiameterAll

example (n : ℕ) [NeZero n] (hn : 4 ≤ n) :
    (LRX.graph n).diam = n * (n - 1) / 2 :=
  LRX.exact_diameter_all n hn
```

Файл [`LRXDiameter.lean`](LRXDiameter.lean) предоставляет то же равенство
под именем `LRXDiameter.exact_diameter`.
Теорема `LRX.sharp_diameter_all` даёт верхнюю оценку, а `LRX.diam_lower` —
нижнюю. Связь графа с моделью списков доказана через `LRX.ListBridge.graphIso`.
Единственность самой далёкой перестановки не утверждается.
Существование слов доказывается классически; исполняемого алгоритма
поиска кратчайшего слова в пакете нет.

## Проверка

После установки [Elan](https://github.com/leanprover/elan), Git, Python 3
и средств сборки выполните:

```sh
git clone https://github.com/snow-ghost/lrx-lean.git
cd lrx-lean
git checkout palomar
lake exe cache get
bash scripts/verify.sh
```

Версии закреплены: Lean 4.35.0 и Mathlib v4.35.0,
коммит `56a005855ea17e0b0958f73ec801ae140b0a1679`.
Файл `lake-manifest.json` содержит точные ревизии всех зависимостей.

Скрипт `scripts/verify.sh` проверяет контрольные суммы исходников,
отсутствие запрещённых конструкций (кроме двух намеренных пропусков
в Challenge), полную сборку и аксиомы всех
проектных теорем. Включены приватные и сгенерированные вспомогательные
теоремы. Разрешены только `propext`, `Classical.choice` и `Quot.sound`;
любая другая аксиома, включая `sorryAx`, завершает аудит ошибкой.
Конечные сертификаты проверяются ядром через `decide +kernel`;
генераторы сертификатов не входят в доверенную основу доказательства.

[GitHub Actions](.github/workflows/lean.yml) повторяет сборку и аудит
при изменениях репозитория. Текущий результат виден во вкладке Actions.
Для каждого процесса Lean установлен предел памяти 8000 МБ;
переменная `LEAN_NUM_THREADS` позволяет уменьшить параллелизм.

## Состав пакета

Доказательство содержит 1137 модулей, файл входа `LRXDiameter.lean`
и проверку `Verify.lean`. Карта основных модулей дана в
[английском README](README.md#proof-structure).

При очистке удалены 66 модулей и 460 деклараций. Все оставшиеся модули
доказательства входят в сохранённое замыкание зависимостей итоговой
теоремы. Вне замыкания оставлены 23 декларации: `simp`-леммы,
производные экземпляры `DecidableEq`, две леммы внутри генерируемых
сертификатов и одна лемма о равенстве по определению, нужная `simp only`.
Исключения сохраняют компилируемость исходников и воспроизводимость
сертификатов; строгая минимальность каждой декларации не заявляется.
Отчёты об очистке находятся в [`provenance/`](provenance/).

Репозиторий содержит формализацию, средства проверки и документацию
к ним. Для сборки и аудита сопровождающая рукопись не требуется.

## Интерфейс Palomar

`Challenge.lean` импортирует только Mathlib и независимо определяет три
хода единичной стоимости, вычисление слова и неориентированный граф Кэли.
Две теоремы утверждают маршрутизацию между любыми перестановками и точный
диаметр для всех n ≥ 4. Два намеренных `sorry` есть только в этом файле
формулировки. `Solution.lean` доказывает обе теоремы через существующие
результаты и мосты, сохраняющие вычисление и длину слов.

После установки Bubblewrap:

```sh
lake build LRXDiameter Solution Challenge
lake env lean Verify.lean
lake comparator --config comparator.json
```

`formalization.yaml` содержит авторов, ответственного сопровождающего
S. Uskov, источники, сведения о помощи ИИ и статус до подачи. Аудит
загружает полные тела приватных и сгенерированных теорем. Записи
`provenance/` описывают исходное извлечение пакета Lean 4.34, а не новую
проверку минимальности после перехода на 4.35.

Для подачи нужны публичный репозиторий, полный SHA коммита, корень
проекта, `comparator.json` и `formalization.yaml`. Регистрация выполняется
отдельно на https://submit.palomar-registry.org/.
